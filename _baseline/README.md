# 회귀 기준선

구조 변경이 계산 결과를 바꾸지 않았는지 검증하는 오라클. 이 프로젝트에는 테스트가 없으므로
이것이 유일한 안전망이다.

## 재생성 / 검증

```
python bench.py < _baseline/answers.txt > /tmp/out.txt 2>&1
diff _baseline/baseline.txt /tmp/out.txt
```

diff가 비어야 한다.

## 주의

- 기준선을 처음 잡을 때는 `PYTHONIOENCODING=utf-8`이 필요했다. 리다이렉트 시 cp949가
  `—`(U+2014)를 인코딩하지 못해 UnicodeEncodeError로 죽었기 때문이다. 지금은 `bench.py`가
  리다이렉트를 감지해 UTF-8로 고정하므로 환경변수 없이 그대로 실행하면 된다.
- `answers.txt`는 `1`을 반복한 파일이다. `1`은 네 입력 헬퍼 모두에서 유효한 유일한 토큰이다
  (`ask_bool`은 `'y'`가 아니므로 False, 나머지는 유효값).
- 따라서 모든 y/n 질문이 False인 경로만 커버한다. 다만 성유물/무기 장착 자체는 답변과
  무관하므로, 슬롯 속성명 변경 같은 조용한 누락은 스탯 시트 변화로 잡힌다.
- `bench.py`의 파티 구성이나 EXPLAIN 대상이 바뀌면 기준선을 다시 만들어야 한다.
- 계산이 **의도적으로** 바뀐 경우(값을 더 정확한 자료로 교체하는 등)에도 다시 만든다.
  그때는 diff를 눈으로 확인해 바뀐 폭이 의도한 범위인지 보고 나서 덮어쓴다.

## 넓게 훑는 쪽 — `tools/stat_sweep.py`

이 기준선은 **한 파티**를 깊게 본다. 스탯 풀 분류(`atk_flat` ↔ `atk_from_pct_share`,
`em_from_flat` ↔ `em_from_pct_share`)를 바꾸는 작업은 특정 조합에서만 값이 달라져
파티 하나로는 변화가 아예 안 보이거나 어디까지 번졌는지 알 수 없다.

그럴 때는 `tools/stat_sweep.py`를 전후로 돌려 diff한다 — 전 캐릭터 솔로 + 변환 캐릭터
페어 + 변환 무기 조합 + 3~4인 파티를 훑고, 스탯 풀을 **조각까지 펼쳐** 찍는다.
둘은 대체재가 아니라 짝이다: 이쪽이 깊이, 저쪽이 넓이를 맡는다.
